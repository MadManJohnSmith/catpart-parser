## 1. Executive summary

The `e5 0d` records are a **13-byte-header length-framed stream**, and they tile the bulk almost completely. Measured over the 128 no-facet parts:

| Measurement | Value |
| :--- | ---: |
| Regions whose content carries an `e5 0d` record run | **108** / 128 |
| … of which the bulk probe's head class is `E5` | 103 (plus 5 it heads as `f64-net`/`other`) |
| Content bytes of those 108 regions | **5,875,872** |
| Bytes inside record runs | **5,797,734** (**0.9867**) |
| Records | **71,609** |
| Runs (clusters) / records per region | 125 / median 324 |
| Regions with **zero** gap between runs | **101** / 108 |
| Interior gap bytes (7 regions) | 4,545 |
| Records whose end lands on the next `e5 0d` marker | **0.9983** |
| Writer blocks at content start (`01 total name`) | **101** (and `content_bytes − total = 131` on 101/101) |
| First-run container declares the exact span | **101** / 101 writer regions |
| Payload bytes (sum over records) | 4,866,817 |
| … classified as f64 arrays / small-count arrays / text / f32 / opaque | **2,180,072** / 214,284 / 12,077 / 43,784 / 2,416,600 |
| f64 triple arrays / array bytes / points | **1,029** / 1,256,352 / **52,348** |
| … that validate as swept grids (≥3×3, ≤1% within-row spread, ≤100 m) | **98** (40 × 18×18, 6 × 60×5, 5 × 24×18, …) |
| … single-row point runs (profiles / limit boxes) | 665 |
| f32 triple grids | **0** |
| `±10.9097` 4-byte words (the brief's "visible f32") | 23,311 |

**Verdict.** The dialect is **framed and measured**: `e5 0d | flag | class:u16le | length:u32le | id:u32le | payload`, closing on the next marker, with the writer block and a fixed trailer as the only systematic residue. Its payloads **do carry exact-geometry coordinates**, as **f64le triples**: 1,029 candidate point arrays, 52,348 points, of which 98 are rectangular pole grids (40 surfaces are 18×18). The brief's "visibly carries f32 coordinates" is a **misreading of isolated 4-byte words**: no region holds an f32 triple grid (`E5-17`), and the longest plausible f32 run anywhere is 55 floats — the byte image of a reference list or a ±1e6 limit box, not an array.

The 98 grids are the second exact-geometry carrier the bulk has yielded (the first was the A/B dialect's f64 pole nets). What is *not* decoded: the payload tag/class vocabulary, the writer block's class table, and the row/column counts of a grid as a stated header field.

## 3. The record law

### 3.1 Grammar and the writer block

```
record:   e5 0d | flag:u8 | class:u16le | length:u32le | id:u32le | payload[length]
                 ^ 13-byte header; next record at +13+length

writer:   01 | total:u32le | name_len:u32le | name[name_len] | tail   (tail = class table)
container:e5 0d | 06 | class:u16le == 1 | field:u32le | span:u32le      (header-only, §3.3)
```

Measured facts, each a claim row:

- The flag is **retained, not whitelisted**. The population shows six values — `0x03` 63,613, `0x13` 4,254, `0x43` 3,035, `0x83` 601, `0x53` 76, `0xc3` 30 (`E5-13`). The low bit pattern (`0x03`) carries the extra bits `0x10/0x40/0x80`; what those bits change is **not decoded**.
- The class is a **16-bit** vocabulary value: 29 classes on `07d3c70b`, top `0x000e` 1,149, `0x0096` 736, `0x01ff` 579, `0x01fe` 386, `0x000d` 386, `0x00a0` 346, `0x00c1` 334, `0x0209` 209 (`E5-06`). Class names are not assigned.
- The id field is **monotone in 100/108 regions** (`E5-14`); it is a stream-level object id, not a per-record index (ids run to 137,136 while a region has 2,957 records).
- **Writer block.** 101 regions open with it. Its `total` satisfies `content_bytes − total == 131` on **101/101** (`E5-11`) — a constant 131 that this probe measures but does not explain. The block is followed by a **variable tail** (4 bytes on `00198dd9`, 8 on `03212512`, 46 on `002e03ea`) that looks like a class/version table (`18 4c 02`, `18 92 0c`, …) and is **not decoded**. Writer names are release stamps: `'  V5R12-HCN:052003'` (48), `'  V5R13-HCN:112003'` (9), `'  V5R19-JMA:112007'` (8), `'  V5R18-FDN:102006'` (8), `'V5 BetaVersion - Not a commercial Product - Volatile'` (6), `'V5R11-TCX:XP'` (5), … — 12 names over 101 regions (`E5-22`).

### 3.2 What the walk measures

A record is admitted only when its 13-byte header parses, its length lands inside the region, and the walk continues: **the length closes on the next `e5 0d` marker**. On the population the closure rate is **0.9983** — of 71,609 records, only the last record of each run (125 runs) is not confirmed by a following marker (`E5-14`).

A run is admitted only with ≥3 chained records and only when it closes on its own end. The result is **contiguous tiling**, and the residue is *structural*:

| residue class | bytes | regions | what it is |
| :--- | ---: | ---: | :--- |
| preamble | 40,863 | 108 | writer block + container + the tag words between them |
| trailer | 32,730 | 108 | tolerances (`0.001`, `1e-3` lane), vendor footer, padding |
| interior | **4,545** | **7** | mid-stream writer block + its container, one 2,270 B block in `c377cd20` |
| **total residue** | **78,138** | | **0.0133 of content** |

**101 of the 108 regions have no interior gap at all**: the record run covers everything between the writer block and the trailer. This is *stronger* than the A/B dialect, whose clusters were separated by unframed f64 allocations of 858–40,392 B. Per-region coverage therefore tracks region size, not unframed content: min 0.9328, median 0.9799, max 0.9991; the 23 regions below 0.95 are the small ones, where a ~280 B preamble + trailer is >5% of the content (`E5-10`, `E5-18`).

The trailer is systematic: median **207 B**, 204–256 B on 84/108 regions, with outliers 457/515/576/1,256 B (`E5-18`).

### 3.3 The container record

`f1 14 00 00` in §2 is not a payload length: read as an ordinary record the same 13 bytes would swallow 78 bytes and land *inside* the run. The container is a **header-only** record whose last `u32le` is the span of the run that follows:

- 106 of 125 runs are immediately preceded by one (`06 01 00` signature);
- **101 of them declare the exact run length** (`E5-12`, `E5-07`) — all 101 writer-region first runs;
- 5 mid-stream containers do not: e.g. `c377cd20` declares 236,446 against a run of 138,124, `d9ad440e` 135,301 against 131,676. Those are the 7 exceptional regions of §2; the field there behaves like a sub-stream span. **Reported, not fitted.**

The `field` slot that would carry a length on an ordinary record is uninterpreted (78, 79, 84, …).

### 3.4 No compression

The bulk probe already measured every 4 KiB window of the 128-region bulk below 7.9 bits/byte (`BS-19`); the E5 spans sit in the same bands (frames ~7.3, arrays ~7.5). Nothing here is a codec.

## 4. The payloads

### 4.1 Census

Per payload the probe measures four renderable shapes at every byte phase — f64 arrays, f32 arrays, small-count arrays (`u32le ≤ 0x0FFF`), printable text — and counts the **longest** one, so the census is a partition and never double-counts a span (`E5-15`). A shape must *vary* to count: mostly nonzero, not dominated by one value, at least four distinct values, and a band that is a visible fraction of its magnitude (this is what keeps a 16-bit reference list from rendering as 55 "floats" of 3.08e-05).

| payload shape | bytes | share | what it is |
| :--- | ---: | ---: | :--- |
| f64 arrays | **2,180,072** | 0.448 | knots, parameters and **pole triples** |
| small-count arrays | 214,284 | 0.044 | multiplicity lists (`6,3,3,3,3,3,3,6`), reference tables |
| text | 12,077 | 0.002 | property names, `Cont_…`, writer strings |
| f32 | 43,784 | 0.009 | small mixed records where an f32 reading outranks the others; **no array** (§4.3) |
| opaque | 2,416,600 | 0.497 | per-record tag/count scaffolding, short values, padding |

Median payload is **28 B**; the stream is a fine-grained object graph, not a bulk array file. The coordinates are concentrated: **64 regions** carry the 1,029 triple arrays, and 1,256,352 B (26% of all payload bytes) are 3-divisible point runs (`E5-16`).

### 4.2 The coordinate arrays

A triple array is the longest 3-divisible run of plausible f64le triples (finite, inside a 100 m envelope, zero allowed). 1,029 such arrays exist. Validation splits them:

- **98 grids** — rows ≥ 3, cols ≥ 3, mean within-row spread ≤ 1% of the axis span, inside 100 m. Shapes: `18×18` ×40, `60×5` ×6, `24×18` ×5, `6×6` ×4, `36×5` ×4, `44×5` ×4, `32×5` ×4, `108×3` ×3, … (`E5-21`).
- **665 single-row point runs** — one station row: a planar profile, a knot lane or a ±1e6 limit box. Reported apart; the bulk probe's `PoleNet.ok` would call these valid, which is why this probe counts grids separately.
- 266 runs are neither (not rectangular, not a single row).

Worked example, `0f0ff88b`:

| block+ | abs | size | field |
| ---: | ---: | ---: | :--- |
| 20,180 | 45,549 | 13 | record: `e5 0d 03 e7 00 77 1c 00 00 4f 02 00 00` → flag `0x03`, class `0x00e7`, `length=7,287`, `id=591` |
| 20,193 | 45,562 | 211 | payload head: `80 05 00 00 00 …` (tag `0x80`, five u32 slots, knot vector, multiplicity list) |
| **20,404** | **45,773** | **10,584** | **pole grid**: 441 f64le triples, **21 × 21** |
| — | — | 24,581 | payload tail (weights/limits, not decoded) |

Decoded values: row 0 runs `(29.197, 13.189, 15.227) … (−5.500, 59.818, 15.211)`; stations advance along **z** (mean within-row z-range 0.0035 mm against a 17.3 mm span, ratio **2.0e-4**), stations are monotone (21/21), AABB x −5.500..29.197, y 12.794..61.492, z −2.092..15.227 mm — a 34.7 × 48.8 × 17.3 mm swept patch at model scale. This is a **point net**, not an evaluated surface: no degree, knot, weight or evaluation is claimed (§4.4).

**Count versus a header field: not established.** The task's third validation leg does not hold cleanly. A candidate exists — on grids whose payload opens with tag `0x80`, `3 × u32le(payload+13)` equals the data-derived row count on **51/98** (`E5-23`, labelled `candidate`). The worked 21×21 grid obeys it (`u32 = 7`), and so do the 18×18 surfaces (`u32 = 6`). But half the grids do not, so the array's extent is validated **two-sidedly by the bytes** — the run begins and ends where the payload stops rendering as plausible model doubles, bounded by the next tag block — and by geometry, **not by a length field the format states about itself**.

### 4.3 The f32 reading

The brief reports the bulk "visibly carries f32 coordinates". Measured:

- The 4-byte words `80 84 2e c1` / `80 84 2e 41` decode as f32 **−10.9097 / +10.9097** and occur **23,311** times in E5 payloads (`E5-17`). They are what makes f32 "visible".
- They **never form an array**: the longest run of plausible f32 values anywhere in the population is **55 floats** (median of region maxima 30), and the 30-float case is the ±1e6 limit box — a run of one magnitude plus an outlier, not 10 triples of coordinates.
- **Zero f32 triple runs validate as grids** (`E5-17`); the f32 path exists and works (a synthetic 6×5 f32 grid is detected by the test suite), so the zero is a measurement, not a blind spot.
- The f32-classified payload bytes (43,784, 0.9%) are small mixed records where no other shape dominates. They carry no point set.

So the coordinates are **f64le triples**. The `±10.9097` words sit inside the per-record tag scaffolding (a value seen in the limit/matrix records of the small parts), not in an array.

### 4.4 What is *not* decoded (named ambiguity)

| span | size | status |
| :--- | :--- | :--- |
| writer-block tail | 4–46 B | class/version table; shape measured (`18 xx 02 …` triples), meaning not |
| `06` container `field` slot | 4 B | uninterpreted (78/79/84) |
| payload tag bytes (`0x80`/`0x81`/`0x18`/`0x38`/…) | 0.5 of payload | a compact object-graph encoding; references (`18 f4 02` ≈ id 756) are *candidate*, not law |
| flag extra bits (`0x10/0x40/0x80`) | — | what they change is not decoded |
| grid row/column counts | — | 51/98 candidate relation only (§4.2) |
| surface tail (24,581 B on the worked record) | — | weights, limits, parameterisation — not decoded |

Consequence: the probe yields **point nets with a measured shape**, not an evaluable NURBS surface and not a typed object graph.

## 5. Population, verdict, next step

### 5.1 Population

- **Law-bearing regions**: 108/128, 5,875,872 B content, 5,797,734 B framed (0.9867), 71,609 records, 125 runs (`E5-10`).
- **Head split**: 101 `writer`, 4 `prefix` (bulk probe: `f64-net`), 3 `bare` (`E5-20`). The bulk probe's `E5` head count (103) and this law count (108) differ by exactly the five regions whose content opens with something else.
- **Control**: the 20 regions that carry no record run are the A/B object-stream dialect (19) and one unclassifiable preamble; they are outside this denominator by construction, not by exclusion after the fact.

### 5.2 Verdict

- **Record law: decoded and measured.** `e5 0d | flag | class:u16le | length:u32le | id:u32le` closes on the next marker at 0.9983 across 71,609 records; runs tile with zero interior gap on 101/108 regions.
- **Writer block and container: measured fields.** `content_bytes − total == 131` on 101/101; the first-run container declares the exact span on 101/101.
- **Payloads: classified.** Half the bytes are tag/count scaffolding; the numeric content is f64 arrays (2.18 MB), of which 1.26 MB are 3-divisible point runs; 98 rectangular grids are the exact-geometry payload.
- **f32 claim corrected.** No f32 array exists in the population; the "visible f32" is 23,311 isolated `±10.9097` words.
- **Ambiguity named**: the tag/class semantics, the writer-block tail, the container `field` slot and the grid counts are undecoded.

### 5.3 Smallest next probe (not taken here)

1. **Decode the payload tag encoding.** Every payload is a compact graph (`80 <u32> …`, `81 18 <u16>` references). The smallest probe is a *format-fit*: take the 71,609 payloads, classify their leading tag runs, and test whether `18 <u16le>` is a reference to a record `id` (it reads as the id of a neighbouring record on several samples). If it fits, the object graph becomes readable and the grid's row/column counts can be looked up instead of guessed.
2. **Join E5 grids to the A/B pole nets.** The A/B dialect carries the same kind of grids in `a5 03 34` frames. A join law (grid bbox ↔ frame) would tell whether the two dialects describe the same surfaces on different parts, and would let the exporter read either.
3. **Resolve the container `field` slot** with the 5 mid-stream containers: they are the only samples where `field` and `span` disagree with the immediate run, so they are the smallest population that can distinguish "span of the next run" from "span of the sub-stream".

## 7. Detector honesty

- **Source of the law.** The 13-byte header is *measured*, not imported: the probe walks bytes, requires a `e5 0d` marker and a length that lands inside the region, and counts a run only when ≥3 records chain and close on their own end. The `class` values are a vocabulary, not proven types; the flag vocabulary is measured (six values), not whitelisted.
- **What "framed" means.** A record is counted when its length closes on the next marker (0.9983 of records) or when it ends the run; the payload is *framed*, not decoded. "Coverage" is bytes inside runs over content bytes; the residue is reported by class (preamble / trailer / interior), not as noise.
- **What "grid" means.** Rows ≥ 3 and cols ≥ 3 from the largest divisor whose rows are near-constant in one axis (≤1% of that axis's span), plus stations monotone **or** not, plus all coordinates inside 100 m. Single-row runs (665) are reported separately because they are profiles or limit boxes, not grids — the bulk probe's looser `PoleNet.ok` would count them.
- **What "shape" means.** The census assigns each payload to its longest *varied* renderable shape; the variety bar (nonzero majority, no dominant value, ≥4 distinct, visible band) is what excludes zero fields and single-magnitude word patterns. The f32 bucket is 0.9% and carries no point set; that is stated, not hidden.
- **What the count check is.** `3 × u32le(payload+13) == rows` is reported as a **candidate** at 51/98. It is not a header field the format states about itself, it does not hold on half the grids, and no array extent depends on it.
- **What is not claimed.** No class/flag semantics, no tag grammar, no knot/degree/weight reading, no surface evaluation, no id↔payload binding. The 5 mid-stream containers whose span does not equal the run are reported and not fitted. The 3 regions without a content-start writer block are reported, not reconstructed.
