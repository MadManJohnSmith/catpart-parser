## 1. Executive summary

| Slice | Verdict | Corpus measurement |
| :--- | :--- | :--- |
| Topology graph | **Assembled** — body/lump/shell/face/loop/edge/vertex with mandatory provenance on every node and arc | 1,317 body and 1,317 lump nodes (BR6G-03a/b); 145 shells (BR6G-03c), 1,495 face nodes (BR6G-03d), 1,523 loops (BR6G-03e), 4,767 loop-segment edges (BR6G-03f), 2,829 vertices (BR6G-03g) |
| Invariants | **4 load-bearing tests + 4 construction guarantees** | 0/76 closed shells pass the loop-segment pairing law (BR6G-05b); 76/76 carry a one-use loop segment (BR6G-05c); 1,322 graphs have no violation at all (BR6G-05a); 0 graphs violate a construction guarantee (BR6G-05d) |
| STEP `exact` | **0 parts** — measured, as predicted | 0/1,442 exports (BR6G-06a); predicted 0/76 closed shells because 0 closed shells are ring-only (BR6G-11c) |
| STEP `facet` (default) | **53 parts** export | 53/1,442 (BR6G-07a), 1,389 refused (BR6G-07b) |

Four facts drive the verdict:

1. **The graph's edges are loop segments, not triangle chords** (contract
   §1/F7). The corpus's 76 closed shells close under the triangle law
   (BR6S-13), but their strip loops are open polylines (BR2-16), so no
   shell pairs its loop segments: 0/76 (BR6G-05b) and 76/76 have a
   one-use segment (BR6G-05c). This is the honest reason `exact` mode can
   never cover the corpus: an exact loop needs a `0x4c` ring with
   `ty == 1` (BR2-15 counts loops, not faces), and of the 522 face records
   inside the 76 closed shells (BR6G-11b) only 101 ring faces exist
   corpus-wide in any placed component (BR6G-11a), with 0 ring-only shells
   (BR6G-11c).
2. **The face family is the normal-bearing planar family.** FaceNodes
   exist for 0x49/0x4a/0x4c only. Down the corpus that leaves 16 component
   records outside the graph (BR6G-11d), 3 of them inside closed shells
   (BR6G-11e, 2 shells — BR6G-11f). Those two shells are why `complete`
   is 64 (BR6G-02) against the shell slice's 66 (BR6S-10): a two-part
   delta, fully accounted for by the face family, not a decoder
   regression.
3. **Composite stores stay unplaceable.** 1,036 parts (BR6G-04; the
   store-class anchor BR6S-08 is 1,036 stores) build a body and the
   assumed lump only: 0 vertices, 0 shells, `status="unverified"`, refusal
   `index-space-unplaceable`. The 116,057 composite face records (BR6S-23)
   are counted unplaced, never remapped onto pool ranks.
4. **The lump is an assumption, not a decode.** BR5-06a reports the
   absence of a lump detector (`observations=0`), not lump cardinality;
   "one lump per body" is `export_label="assumed"` and blocks export
   unless the caller sets `accept_assumed_lump`. 1,317 lumps per 1,317
   bodies (BR6G-10a) is that assumption applied, and 0 unknown-labelled
   nodes reach any graph (BR6G-10b).

## 2. The byte anchor (both bases)

The graph decodes no new bytes: its carrier is the facet record, cited
here with both offset bases so every figure traces to a position. Grammar
(G3/BR2, unchanged):

| offset | field |
| :--- | :--- |
| `+0x00 (0d)` | record marker `01` |
| `+0x01 (1d)` | facet marker `mk` (`0x41`-`0x4f`; FaceNodes are the normal-bearing `0x49`/`0x4a`/`0x4c`) |
| `+0x02 (2d)` | `ty` = loop count (BR2-07) |
| `+0x03 (3d)` | form byte `ff` (4-byte header form) |
| `+0x04 (4d)` | `u32le n` — reference count (`+0x04 (4d)`..`+0x08 (8d)`) |
| `+0x08 (8d)` | 12B normal, f32le `nx`/`ny`/`nz` (`+0x08 (8d)`, `+0x0c (12d)`, `+0x10 (16d)`; normal-bearing markers only) |
| `+0x14 (20d)` | `ty` count integers (`u8` or `u16be`, per-record width) |
| counts end | `n` references, `u8`/`u16be`, **lexicographic ranks** into the pool (G3 F2/C8) |

`FaceData.record_offset` is the anchor every face/loop provenance row
cites (`record+0x…`); vertex provenance cites `pool[rank=…]`.

## 3. The graph model

Seven node kinds (body, lump, shell, face, loop, edge, vertex), six arc
kinds (`body-lump`, `lump-shell`, `shell-face`, `face-loop`, `loop-edge`,
`edge-vertex`). Every node and every arc carries the five provenance
facts (decoder, construct, claim, labels + nominated `export_label`,
index_space) plus scope, unit and byte/store anchor. The claims allowlist
resolves each id against the committed `br*claims*.csv` rows and checks
the cited row's **scope** against the node's index space; this note's own
`br6-graph-claims.csv` is excluded (a note cannot justify its own graph).

What the corpus graph contains, per row:

- body = lump = 1,317 (BR6G-03a/b): exactly one body per located store is
  a declared assumption in the body provenance (BR5-04a/b prove
  container/root, not a count). 125 parts carry no validated store
  (row-derived 1,442 − 1,317; BR6S-02 observations, BR6S-06 passes) and
  yield a body-less graph with `status="unverified"`.
- shells = 145 (BR6G-03c), the same 145 components the shell slice
  decodes (BR6S-13 observations). 76 are closed (BR6G-05b observations).
- faces = 1,495 (BR6G-03d). The number ties out BR2-10's pool-only face
  denominator (1,495) because both count the normal-bearing placed family.
- loops = 1,523 (BR6G-03e); edges = 4,767 (BR6G-03f) — loop segments, not
  triangle chords; vertices = 2,829 (BR6G-03g) — pool slots, no welding
  and no dedup (T07_pool_count_law); the 531 out-of-pool records (BR6S-20)
  contribute none.

`check_invariants` returns violations, never raises. 1,322 of 1,442 graphs
have no violation of any kind (BR6G-05a); the remaining 120 (row-derived
1,442 − 1,322) carry exactly the loop-segment pairing/orientation failures
below. No graph violates a
construction guarantee (BR6G-05d = 0): no orphan, homogeneous index
space, dense ids in store order, legal acyclic arc kinds.

## 4. Surface coherence (rings vs strips)

The rule is split by loop family (contract §2/F2), because
`quadrics.classify_strip_patch` is a strip law:

- **Rings (0x4c)**: the record's stored plane only (BR2-10 coplanarity,
  BR2-06 unit normal). Calling the strip classifier on ring refs would
  return `degenerate` (3 refs) or `pencil-noncyl` (4+); that is
  construction, not geometry, so it is never called.
- **Strips (0x49/0x4a)**: per-loop `PatchFit`. PLANE iff every loop is
  planar/degenerate and the record plane passes; CYLINDRICAL_SURFACE iff
  every loop fits one cylinder with axis agreement by cosine
  (`>= 0.999`) and radius agreement relative (`<= 1e-2`). Cone, sphere,
  pencil and curved fits stay loop readings and never become a face
  surface (BR4 §4). Mixed loops set `surface_disagreement`.
- Both supported surfaces are `label="candidate"`: a planar patch may be
  a curved surface's tessellation (SRF-01), and a torus band is a valid
  cylinder at either equator (SRF-05's upper bound, 67,919 classified
  loops). SRF-06 has no separable signature and is never emitted; SRF-07
  stays candidate.

No corpus figure is claimed for surface counts here: the corpus shell
faces are strips and their planar/cylinder readings are per-loop floors
(BR4), and this slice's own rows count nodes, not surfaces.

## 5. Invariants: 4 load-bearing, 4 construction guarantees

Load-bearing (negative fixtures in `tests/test_brep_graph.py`, roster in
`--selftest`):

1. **edge-use-pair** — every undirected loop segment is used exactly
   twice. Corpus: 0/76 closed shells pass (BR6G-05b); 76/76 carry at least
   one one-use segment (BR6G-05c). The `exact`-mode refusal is
   `shell-not-brep-paired` (64 parts, BR6G-06b); it is a different law
   from the triangle closure that made those shells (BR6S-13).
2. **orientation** — no directed loop segment twice. Same corpus
   population as the pairing law; it fires through the same class.
3. **provenance-complete** — every node, surface claim and arc, with the
   claim allowlist and the scope/index-space check. 0 violations
   corpus-wide (part of BR6G-05a); a fabricated id or a composite-scope
   row on a pool node fails the synthetic fixtures.
4. **no-guess** — `unknown` never ships (`0` unknown nodes, BR6G-10b);
   `derived`/`assumed` need a stated basis; the assumed lump refuses until
   accepted (fixture and `--selftest`).

Construction guarantees (reported, never load-bearing — F8):

5. **no-orphan**, 6. **index-space-homogeneous**, 7. **determinism**,
8. **arc-kind-table**: 0 corpus graphs violate any of them (BR6G-05d).
Determinism is also the export's own property: the first facet-mode
success rendered twice is byte-identical, sha256
`d37e973da3bdf6a340250556c5b445d70cd425e2822ff972b5cf7171553ebc68`
(BR6G-08; the digest lives in the row's statement because the family's
`value` column is numeric, and `value=2` is the number of renders
compared).

## 6. STEP export

`facet` is the default; `exact` is the strict mode. Both need a
caller-supplied length unit (no model unit is decoded — units are a
documented negative, U2) and, for corpus graphs, acceptance of the assumed
lump, so the refusal measured below is the graph's property, not a policy
default.

**`exact` — 0 parts (BR6G-06a).** Predicted before the run as 0/76 closed
shells, because exact needs a `0x4c` ring with `ty == 1` and 0 closed
shells are ring-only (BR6G-11c); the 522 face records of the 76 closed
shells (BR6G-11b) carry only 101 ring faces corpus-wide (BR6G-11a). The
strict-order class distribution sums to 1,442:

| exact refusal class | parts |
| :--- | ---: |
| `index-space-unplaceable` (composite stores) | 1,036 |
| `body-no-shell` (no store, face-free store, no placeable face) | 283 |
| `face-family-unread` (0x41/0x42 inside a component) | 10 |
| `shell-open` | 49 |
| `shell-not-brep-paired` | 64 |

`body-no-shell` = 283 is row-derived and exact: 125 parts without a store
(1,442 − 1,317), 128 pool-only stores without a face record (281 − 153:
BR6S-07 minus BR6S-09 observations) and 30 stores that place no face
(BR6S-12). `shell-not-brep-paired` = 64 = 66 parts with a closed shell
(BR6G-01) minus the 2 whose shells carry an unread record (BR6G-11f).

**`facet` — 53 parts (BR6G-07a), 1,389 refused (BR6G-07b).** The class
distribution is the same shape with two mode-specific additions:
`loop-role-undecided` 9 parts (multi-loop faces, BR2-09) and
`shell-role-undecided` 2 parts (more than one closed shell; positive
signed volume does not identify a cavity, BR6S-17/18), plus
`index-space-unplaceable` 1,036, `body-no-shell` 283,
`face-family-unread` 10, `shell-open` 49. Multi-loop faces are the 9
`loop-role-undecided` parts (BR2-09's 2,331 multi-loop records corpus-wide);
count-variant faces (BR2-07d's 82 normal-bearing records) refuse as
`face-count-variant`, which is 0 as a strict-first class in this run
(BR6G-07c_facet_refusal_face-count-variant).

The file itself is the contract's B-rep subset: no product structure,
`FILE_DESCRIPTION` naming this contract and the face mode, no `B_SPLINE`,
no `TOROIDAL_SURFACE`, no `CONICAL_SURFACE`/`SPHERICAL_SURFACE`/
`SURFACE_OF_*` and no silent plane substitution. Floats are pinned
(`-0.0 -> "0."`, 9 significant digits for pool f32, 12 for derived
values), and `write_step` never writes a refused graph.

## 7. Detector honesty — what the graph does NOT discriminate

- **Composite index space.** The graph does not decode the element space
  (1,036 stores, BR6S-08; 116,057 face candidates, BR6S-23). It does not
  label a node `composite-element` and remap it; it builds no placeholder
  geometry and refuses the export. `skipped_refs` stays 0 in every graph
  (BR6G-09b) — BR4's 78,255 skip refs and 90,451 excluded loops over
  156,914 composite loops (`composite_loops_excluded_share`) are **cited,
  not re-derived**.
- **0x44 unread records.** Counted in `Completeness.unknown`, labelled
  `unknown`, never noded: 708 corpus-wide (BR6G-09a), exactly the shell
  slice's 0x44 population (BR6S-22). The graph does not decode the
  marker's primitive reading.
- **Face family.** 16 component records lack a FaceNode producer
  (BR6G-11d), 3 inside closed shells (BR6G-11e). The graph does not
  fabricate a face from a record without the 12B normal; it counts it and
  refuses `face-family-unread`.
- **Loop segments ≠ triangle edges.** The pairing law is not the shell
  slice's closure law, and BR6S-16 counts directed **triangle** edges, not
  loop segments. A shell can be `closed-manifold` and still fail the B-rep
  pairing (76/76 do, BR6G-05c); the graph labels the difference and the
  export refuses, it never substitutes one law for the other.
- **Lump cardinality.** BR5-06a is a detector negative. The graph does not
  claim a decoded lump; it declares the assumption, labels it, and blocks
  export until the owner accepts it (BR6G-10a shows 1,317 assumed lumps
  for 1,317 bodies — an assumption, not a measurement).
- **Body count.** One body per located store is declared an assumption in
  the provenance detail (BR5-04a/b prove container/root only).
- **Record ≠ face, closed ≠ B-rep, chord ≠ curve.** Face nodes carry
  `("fact","inference")`; shells carry `derived`; the first
  `FILE_DESCRIPTION` line names the contract and the face mode, so a
  faceted shell cannot be read as an exact B-rep.
- **CYLINDRICAL_SURFACE in `exact`.** Unreachable (a ring's surface is the
  record plane), so it is refused `unsupported-surface` rather than
  silently translated. The writer path exists because the contract pins
  the entity and is exercised by a direct unit test.
- **Gaps left unimplemented, with reasons.** (a) No loop-role assignment:
  the contract has no caller API for outer/inner, so `ty > 1` refuses in
  both modes. (b) No composite element decode (BR5 landed without one;
  contract §7.1). (c) No first-class edge/vertex records: no face binding
  exists (BR3 §4). (d) No schema-valid product structure: the entity
  subset is the contract's, not an AP214 part. (e) The ISO schema
  identifier strings remain corpus-unverified.

    --selftest

modes, determinism, lump assumption, open sheet, composite store) with no
corpus. The corpus run is deterministic: a second run to a temp path
produced a byte-identical CSV (verified 2026-11-18), and the STEP digest
row is reproduced by the selftest. Corpus binaries are read read-only from
the main checkout; nothing is copied into the tree.
