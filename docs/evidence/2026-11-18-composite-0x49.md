## 2. The asymmetry, and why the marker was not enough

`GATED` (composite.py) always included `0x49`: its references were bounds-checked
as element indices. `_triangulate`'s emission set did not, so a 0x49-only store
decoded its element space, gated its refs, counted zero exportable records and
exported **vertices without faces** — the L2 `empty-mesh` class. The clean path
(`facets.decode_soup`, `SOUP_MARKERS = STRIP_MARKERS + POLY_MARKERS` with
`0x49` in `STRIP_MARKERS`) had no such asymmetry, which is what made the
composite gap a bug rather than an open question.

Adding `0x49` to the emission set alone is not sufficient: the generic
`(width, k)` count search misreads the family. That is why this ticket pins the
record law before exporting (the ticket's "if the 0x49 count law differs, pin
it with committed rows" clause).

## 3. The pinned law (byte anchor + corpus census)

### 3.1 The byte anchor — gopro3, record at `565376`

```
01 49 01 ff | 03 00 00 00 | b5 11 25 bf 9d cf fe be 3d 83 14 bf | 03 28 05 17 00 8a
header      | n = 3       | normal (-0.6448, -0.4977, -0.5801)   | refs (u16be)
```

| field | position | value |
| :--- | :--- | :--- |
| marker | `+0x01` | `0x49` |
| `ty` | `+0x02` | `1` |
| form byte | `+0x03` | `ff` (4-byte header) |
| `n` | `+0x04` | `3` (`u32le`) |
| normal | `+0x08` | 12 B f32le |
| refs | `+0x14` | **no count bytes**, `n × u16be` = `0x0328`, `0x0517`, `0x008a` |

The record is **26 bytes** and the 0x49 headers in this store are **26 bytes
apart for 795/795 consecutive pairs** — every record tiles exactly. The
elements `808, 1303, 138` decode to three points coplanar with the stored
normal at **3.30e-08**.

The generic law reads `03` as a count and `28 05 17` as u8 refs, leaving the
two bytes `00 8a` before the next header. That misparse is what produced the
earlier "118 records / 125 loops / 116 nonplanar welds" reading: the first
reference's high byte (an element index's top byte) was consumed as a count byte.
The family's own reader removes the guess.

What the detector does **not** discriminate (honesty line):

- It does not pin a *plane offset*: only the normal's coplanarity is tested
  (the plane offset is derived, never stored — BR2 SRF-01).
- It does not explain the 394 candidates whose ref block overruns the next
  header (they are rejected); the 365 non-exact candidates that end before a
  following header are accepted under the committed "at or before the next
  header" tiling term, the same term the 0x42 law uses.
- It does not pin the 5-byte header form: the law is the 4-byte form
  (`01 49 ty ff`), and a 5-byte candidate stays unresolved (zero accepted
  corpus records use that form — BR2-17).
- The 2,257 multi-triangle records (`ty > 1`, up to `ty = 86`) split into
  `ty` 3-ref loops by construction; the split is the law, not a search.

### 3.3 The reading the law implements

```python
def parse_049_record(data, o, nxt, n, normal, element_count):
    ty = data[o + 2]
    if n != 3 * ty:                     # BR2-18b, the family predicate
        return None
    end = o + 20 + 2 * n                # no count table
    if end > nxt:                       # the committed tiling term
        return None
    refs = (u16be at o+20, ...)         # u16be element indices
    if any(r >= element_count):         # fail-closed refs gate
        return None
    return (o, 0x49, normal, (3,) * ty, refs, 2)
```

The returned `counts` are `ty` loops of three references, so `_triangulate`
treats the record as a triangle list under the **same** strip window as
`0x42`.

are recovered**; the third had already been unblocked by a different family.

## 5. The structural acceptance the admission rides on

No new topology rule was introduced. The admission is exactly the 0x42
treatment, with the family's reader in front:

1. **Count/tiling law** — `parse_049_record` (`n == 3*ty`, exact-or-before
   tiling, in-space refs). The same terms the 0x42 path uses, applied to the
   family's actual record shape.
2. **Written loops** — the strip sliding window (`_loop_triangles`), the G3 F7
   degenerate skip, exactly like 0x42/0x4a.
3. **Skip-bearing loops** — the committed per-loop dup-pin weld
   (`_e0b_dup_pin`): fully pinnable, **coplanar against the stored normal at
   `PLANE_TOL`**, no degenerate emission, and the shared incremental edge-use
   guard (`_mesh_safe`) keeps the assembled mesh manifold. A loop failing any
   test stays dropped and counted — no marker-specific bypass. gopro3 is the
   live witness: 730 loops weld, and the resulting mesh closes (0 boundary
   edges) because the pins land on the ring.
4. **Refs gate** — `GATED` already included 0x49; the reader additionally
   rejects out-of-space refs at the record level (the same fail-closed rule).

A per-record assembly gate (the extended-header lever) was **not** added: with
the law pinned, the A/B measures 0 pass→fail and 0 manifold regressions without
it, and adding it would make 0x49 stricter than the 0x42 family it is admitted
on the terms of. The existing guard already covers the only structural risk
(skip-bearing loops).
