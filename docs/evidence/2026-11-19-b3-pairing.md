## 1. The law

**The pool wrapper FOLLOWS its rep node.** In a per-rep store the
`01 06` pool group whose wrapper follows a list node belongs to that
node: the pairing is positional (`_rep_node_positions`, port
`rep_node_positions`) — the last token-bearing node before the group's
wrapper. A node already claimed by an earlier group cannot re-list a
second pool (the later group gets `None` → fail-closed); there is no
"first node after the wrapper" fallback (it absorbs 0/24 on the
measured multi-rep population, and 2 of 1,186 in the wider scan, both
times with the preceding node absorbing as well).

The old reading paired the k-th group with the k-th **decoded** node.
That is the same pairing only while every node decodes; the moment one
node fails its walk, every later rep shifts by one and reads the wrong
element space. B3 pairs by node position, so a rep that does not decode
stays unexported and the next group keeps its own node.

A rep's record territory is `[region_end, next token node)` — the next
scanned node, decoded or not — so an undecodable rep's records are never
attributed to its predecessor (Python `_decode_per_rep`, Rust
`decode_per_rep`; same in `_decode_mixedwrite` / `decode_mixedwrite`).

Each paired node decodes under the per-rep law ladder
(`_decode_rep_node` / `decode_rep_node`): the committed table layout
first (every rep the path already decoded keeps that exact reading),
then the stage-8 extent / raw / flat laws with the rep's OWN pool group
as the flat law's absorption reference. A multi-rep store's concatenated
pool can never re-list in one region; the twins' 8-vertex groups re-list
8/8 in their own flat region and 0/8 against the other rep's.

Store-level gates are unchanged: absorption per rep, the M2b refs gate
against the rep's own element count, the primary-emit seam, the
stage-15 dedup and the 0x49 / extended-header families all run exactly
as committed.
